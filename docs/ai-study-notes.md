# 用 AI 把课件整理成学习笔记

把这份文件和新的 slides 一起发给 AI，再发下面的启动语。先看问题大纲，用编号选择接下来要学的内容，例如「讲第 7 节」或「先讲 7.1 和 7.2」。

> 请按附件《用 AI 把课件整理成学习笔记》里的方法学习我上传的 slides。先给我一份问题驱动的知识大纲，每节标出 Slides 页码，节内用 1.1、1.2 这样的编号列出具体问题。先停在大纲，等我点名再展开。课程、周次和范围以我给出的信息和附件为准。

如果只上传 slides，就复制下面的完整提示词。可以在开头指定范围，例如「先给我第 5–12 页的大纲」。

## 完整提示词

```text
请用我附上的 slides 或 PDF 带我学习，并把逐节完成的内容写成可复习、可放到 GitHub 的中文学习笔记。课程、周次和范围以我给出的信息和附件为准。

先读课件
- 确认这部分的主题、前置知识、主要结论和题型。按理解所需的顺序组织正文，可以合并讲同一件事的多页。
- 保留课件的正式定义、假设、输入范围、符号和术语。图、表或公式有歧义时，能看原页就核对原页。读不到的地方指出页码或标题，并说明缺了什么。
- 关键定义、定理和课件例题尽量给出课件名与 PDF 页码，页码不确定时用 slide 标题。自己补的例子标为「自编例子」，从题目推断的考法标为「练习变式」。

第一轮只给问题驱动的知识大纲
- 标题用「课程 Week N 知识大纲 — 本周主题」。按课件内容拆成具体的知识板块，一级标题编号为 1、2、3，并保留核心英文术语和中文说明。
- 每节标题下面标出实际覆盖的 Slides 范围，例如「Slides 4–8」。优先使用讲义显示的 Slide 编号。若用 PDF 页码，注明「PDF 页」。练习题可标 Tutorial 题号或模拟卷题号。页码无法核实时，引用 slide 标题。
- 把每节内容写成可直接提问的具体问题。按章节编号写 1.1、1.2、1.3，到了第 7 节就写 7.1、7.2、7.3。每题单独一行。问题行直接以编号开头，省去项目符号。
- 问题跟着知识走。可以问术语是什么意思、和前面学过的概念有什么关系、公式里数的是什么、具体例子怎么跑、某个条件改了会怎样、考试遇到时要做什么。用课件中的术语和例子，把「理解核心概念」这样的泛泛目标写成能直接回答的问题。
- 大纲列完就停。定义、例题步骤、证明、答题模板和闭卷题放到相应小节的讲解里。等我点名，例如「讲第 3 节」或「先讲 7.2」。如果我在开头已经点名要讲的小节，就直接讲该小节。

我点名后，按这个顺序展开选中的内容
1. 开头用一句大白话回答「这节在解决什么问题」，再给一条短的知识路线。能接上之前学过的概念时，解释旧概念能做到哪一步，以及这节多解决了哪一步。
2. 先给直觉和典型使用场景，再给正式定义。第一次出现的英文术语先用一句中文说清意思，之后保留英文，方便对照 slides 和考题。解释公式里的符号、每个量代表什么，以及条件什么时候成立。
3. 每个核心难点至少用一个小例子讲透。遇到题先带我读题，把题目翻成大白话，说清给了什么、要我输出什么、哪些限制会影响做法。随后按「当前是什么 → 这一步做什么 → 为什么能这样做 → 结果是什么」走完。能显示中间状态时，写出具体的输入、状态或变量变化。
4. 给一个只改一处的对照例子或反例，说明结果为什么变了。优先挑我容易混的边界，例如空输入、恰好一次、至少一次、符号相似但含义不同。反例要指出它违反了哪条条件。
5. 适合出题的内容最后提炼为「看到什么题眼 → 用什么方法 → 按什么步骤写 → 怎么检查」。至少给一个改题条件后的练习变式，并说明原模板哪一步要调整。需要证明时，先用大白话解释证明逻辑，再给能写进考卷的简短版本。题目用英文时，给一段可直接改写的英文作答模板。

不同内容怎么展开
- 状态机或递推过程：先定义每个状态或变量的含义，再完整跑一条输入。方便时用小表列出当前状态、读到的符号、下一状态和剩余输入。最后明确何时判定结果。
- 算法或构造：先说明为什么这样做，再展示每一步如何得到下一个状态，最后说明正确性依赖的条件。涉及复杂度时，先说 n 代表什么、数的是什么操作。
- 证明或反例：先说要证明的命题和量词顺序，再解释证明里的关键一步。用小例子帮助理解，但把一般性的理由写出来。
- Compare、Define、Explain、Construct、Prove 等题目：说清动词要求的交付物，以及一份完整答案要写到哪里。

讲完选中的内容后再复习
- 给 3–6 条能脱离正文看的速记句，重点是可以拿来判断或做题的规则。
- 给 3 道闭卷题，分别考复述概念、手算或走步骤、做一道小变式。把答案统一放到后面。
- 把最容易出现的误判整理成「我可能会怎么想 → 错在哪里 → 下次用什么规则检查」。用 1 天和 1 周两个回顾点，分别重做容易错的一步和变式题。

输出和后续编辑
- 用自然的中文博客口吻写，短段落，术语保留英文。一个 H1，下面用 H2 和 H3 组织。关键规则可以加粗，表格留给需要对照或跟踪状态的内容。
- 默认给 UTF-8 Markdown 正文。简单符号可直接写 ε、∅、→，把术语和短表达式放在反引号里。用复杂公式前先看目标平台能否渲染。若我要求在聊天里直接修改，优先用对方支持的可编辑文稿模式。
- 公开版本用自己的话讲解，优先使用自编例子和自行绘制的图。课件原图、原文或题目全文需要有相应的公开使用权限。
- 如果我说「这段没明白」，先复述我卡住的那一步，用更小的输入重讲一次，再帮我把理解整理成能贴回正文的一段。如果我已手改某个章节，只修改我点名的范围。
```

## 点名后的讲解示例

### DFA 怎么判断一个字符串以 `a` 结尾？

题目要你造一台机器，读完 `{a, b}` 上的整个字符串后，判断最后读到的是不是 `a`。

这台机器只需要记住一件事：**目前最后读到的字符是 `a` 吗？** `q0` 表示还没读字符，或最后读到的是 `b`。`q1` 表示最后读到的是 `a`。从 `q0` 开始，把 `q1` 设为 accepting state。

从任一状态读到 `a` 都去 `q1`，因为最新的最后一个字符变成了 `a`。从任一状态读到 `b` 都去 `q0`，理由相同。

自编例子，输入 `aba`：

| 步骤 | 读到的字符 | 当前状态 | 剩余输入 |
| --- | --- | --- | --- |
| 开始 | 尚未读取 | `q0` | `aba` |
| 1 | `a` | `q1` | `ba` |
| 2 | `b` | `q0` | `a` |
| 3 | `a` | `q1` | `ε` |

`aba` 被接受，因为读完时停在 `q1`。对照输入 `abb`，读第一个 `a` 后也会到 `q1`，但读完后停在 `q0`，所以拒绝。看到中途进入 accepting state 时，先检查是否还有输入。

**考试怎么写。** 题目出现 `ends with a` 时，先用状态记录最后读到的是不是 `a`，再补齐每个状态对 `a` 和 `b` 的转移，最后用 `ε`、`a` 和 `abb` 检查。若题目改成 `starts with a`，修改的是状态的含义和后续转移：首字符读完后，结果就已经确定，之后的字符不会改变它。

## 放进这个 GitHub 仓库

生成笔记时可以在提示词末尾追加这一句：「这篇要放进 `Mccrree/Mccrree.github.io`。先读仓库 `README.md` 和对应课程的 manifest，按现有约定给出 Markdown。」

- COMP2022 以 [`data/comp2022.json`](../data/comp2022.json) 为准。Week 文件用 `content/comp2022/NN-slug.md`，Tutorial 用 `content/comp2022/NN-slug-tutorial.md`。首个非空行使用 manifest 中对应的标题作为唯一 H1。
- 直接写 Markdown 正文。站点会生成 Hexo front matter。图片放在与 Markdown 同名的资源目录，引用方式见 [仓库 README](../README.md)。其他课程按 README 找到对应的 manifest 和正文目录。
- 写入后运行 `npm run check`。核对通过后，按仓库流程提交并推送，`main` 上的变更会触发站点构建。

想看完整的现有风格，可以读 [Week 5 的 Automata 笔记](../content/comp2022/05-automata-ii.md) 和 [Tutorial 06 的解题笔记](../content/comp2022/06-context-free-grammars-i-tutorial.md)。
